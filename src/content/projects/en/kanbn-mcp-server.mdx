## The Problem: the Board Is Out of the Agent's Reach

Kanbn is an open-source, Trello-style Kanban board that can run on your own infrastructure. An AI agent that helps with planning needs to see that board and act on it. Without that, every conversation starts from scratch and context is carried by hand.

## Architecture

<AsciiPiece piece="kanbn-en" label="An MCP client such as Claude or Cursor talks over stdio to kanbn-mcp-server, which calls the Kanbn REST API over HTTPS using an API key." />

The server runs as a local process of the MCP client (`node dist/index.js`) and speaks JSON-RPC over stdio. Each tool becomes an authenticated REST call to the Kanbn API.

## Exposed Tools (15)

| Area | Tools |
|---|---|
| **Workspaces** | list, get and search boards and cards |
| **Boards** | list, get (with columns and cards), create, update and delete |
| **Lists (columns)** | create, rename or move, and delete |
| **Cards** | get, create, update or move across columns and positions, and delete |

## Design Decisions

- **Environment-based config:** the instance URL and API key come from environment variables, never from code. The repository ships only a `.env.example`.
- **Client-agnostic:** the same server works in Claude Desktop, Cursor or any MCP client with an `mcpServers` block in its config file.
- **Clear scope:** the server translates protocol. Business rules and permissions stay in the Kanbn API.

## How It Relates to the Rest of the Portfolio

It is the same protocol that [Retroyrd](/en/projects/retroyrd/) exposes at `/mcp` so agents can take part in retrospectives. Here MCP is the product: a bridge between AI and a tool the team already uses.
