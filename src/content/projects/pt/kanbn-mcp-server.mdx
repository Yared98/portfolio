## O Problema: o Quadro Fica Fora do Alcance do Agente

O Kanbn é um quadro Kanban de código aberto, no estilo Trello, que pode rodar na própria infraestrutura. Um agente de IA que ajuda no planejamento precisa enxergar esse quadro e agir sobre ele. Sem isso, cada conversa começa do zero e o contexto vai à mão.

## Arquitetura

<AsciiPiece piece="kanbn-pt" label="Um cliente MCP, como Claude ou Cursor, conversa por stdio com o kanbn-mcp-server, que chama a API REST do Kanbn por HTTPS usando uma chave de API." />

O servidor roda como processo local do cliente MCP (`node dist/index.js`) e fala JSON-RPC por stdio. Cada ferramenta vira uma chamada REST autenticada à API do Kanbn.

## Ferramentas Expostas (15)

| Área | Ferramentas |
|---|---|
| **Workspaces** | listar, detalhar e buscar boards e cards |
| **Boards** | listar, detalhar (com colunas e cards), criar, atualizar e excluir |
| **Listas (colunas)** | criar, renomear ou mover, e excluir |
| **Cards** | detalhar, criar, atualizar ou mover entre colunas e posições, e excluir |

## Decisões de Projeto

- **Configuração por ambiente:** URL da instância e chave de API vêm de variáveis de ambiente, nunca do código. O repositório traz só um `.env.example`.
- **Independente de cliente:** o mesmo servidor funciona em Claude Desktop, Cursor ou qualquer cliente MCP, com um bloco `mcpServers` no arquivo de configuração.
- **Escopo claro:** o servidor faz tradução de protocolo. A regra de negócio e as permissões continuam na API do Kanbn.

## Relação com o Resto do Portfólio

É o mesmo protocolo que o [Retroyrd](/pt/projects/retroyrd/) expõe em `/mcp` para agentes participarem de retrospectivas. Aqui o MCP é o produto: uma ponte entre IA e uma ferramenta que a equipe já usa.
